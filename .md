### SPEC-000: Fundación del Proyecto - TaskFlow Lite

#### 1. Propósito
Establecer las bases técnicas, arquitectónicas y de gobernanza para el desarrollo de TaskFlow Lite, asegurando un entendimiento compartido entre el equipo y alineación con los principios de desarrollo guiado por especificaciones (Spec-driven development), sin implementar todavía funcionalidad de negocio.

#### 2. Alcance

```text

```

#### 4. Restricciones Técnicas
* **Lenguajes y Estándares:** HTML5 semántico, CSS3 moderno y JavaScript (ES Modules nativos).
* **Ausencia de Frameworks y Librerías Externas:** Prohibido el uso de librerías de terceros, frameworks de JavaScript (React, Vue, etc.) o frameworks CSS (Bootstrap, Tailwind). Todo se desarrollará con tecnologías nativas del navegador.
* **Persistencia:** Almacenamiento local mediante la API de LocalStorage, encapsulada de manera limpia sin acoplar la lógica de negocio.
* **Entorno de Ejecución:** Ejecutable localmente abriendo `src/index.html` en cualquier navegador moderno o mediante un servidor de desarrollo local (como Live Server en VS Code).

#### 5. Convenciones de Nombres
* **Archivos y Directorios:** Minúsculas y separados por guiones medios (`kebab-case`), por ejemplo: `styles.css`, `app.js`.
* **Variables y Funciones (JS):** `camelCase` (ej. `taskList`, `saveTask`).
* **Clases CSS:** `kebab-case` orientadas a componentes o estados (ej. `task-card`, `is-completed`).
* **Atributos de IDs y Clases en HTML:** Claros, descriptivos y en inglés o español coherente (preferentemente inglés técnico estándar para código, ej. `task-container`).

#### 6. Convenciones de Git
* **Commits:** Uso de Conventional Commits (ej. `feat:`, `fix:`, `docs:`, `chore:`).
* **Ramas:** Ramas basadas en especificaciones o iteraciones (ej. `feature/p01-task-registry`, `spec/spec-000-foundation`).
* **Historial:** Commits atómicos, limpios y descriptivos centrados en un solo cambio lógico.

#### 7. Definition of Done (DoD) Técnica Inicial
Una tarea o incremento técnico se considerará "Terminado" cuando cumpla con lo siguiente:
* El código respeta estrictamente las restricciones técnicas (sin frameworks, puro Vanilla JS con ES Modules).
* La estructura de archivos se mantiene alineada con la ruta definida en `/src`.
* No genera errores ni advertencias en la consola del navegador.
* Cuenta con instrucciones claras de verificación técnica para comprobar su correcto funcionamiento local.

#### 8. Fuera de Alcance
* Implementación de lógica de negocio o historias de usuario (crear, listar o actualizar tareas).
* Configuración de servidores backend, bases de datos remotas o despliegues en la nube.
